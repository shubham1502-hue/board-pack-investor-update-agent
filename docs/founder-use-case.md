# Founder use case

## Operating problem

Founders often have the numbers but not the board narrative. The operating pain is converting MRR, churn, CAC, burn, runway, activation, and pipeline into a clear story about what changed and what decisions are needed.

## What the founder gets

- board pack
- investor update draft
- risk list
- decision list
- metric charts
- HTML report
- JSON analysis

## Best first use

Use this repo when the operating question is: This is not an investor update template. It is a reporting workflow that connects metrics to board-level decisions.

## What to bring

- metrics CSV with month, MRR, churn, CAC, burn, runway, activation, pipeline, and notes where available
- company context file
- optional LLM provider settings in `.env`

## Decision artifact

The useful output is not the repo itself. The useful output is the memo, scorecard, template, CSV, dashboard-ready file, or operating cadence that helps the founder decide what to do next.
